ABSTRACT

The financial trading landscape has undergone a significant transformation over the past decade, with retail traders gaining unprecedented access to global markets through online brokerages and trading platforms. However, the vast majority of retail traders struggle to achieve consistent profitability. Industry studies consistently indicate that over 80% of retail traders lose money, with the primary causes being poor discipline, lack of a structured trading plan, inadequate record-keeping, emotional decision-making, and the absence of systematic performance analysis.

Existing trading tools are highly fragmented — traders must use separate applications for journaling, charting, news aggregation, algorithmic trading, and performance analytics. Spreadsheets remain the most common journaling tool despite their limitations in automation, visualization, and insight generation. Premium platforms like Tradervue and Edgewonk offer specialized journaling but lack algorithmic trading capabilities and AI-powered coaching. This fragmentation leads to inefficiencies, data silos, and missed opportunities for cross-referencing trade data with broader market context and psychological patterns.

TradeOS is a comprehensive, full-stack web application designed to address these challenges by providing an integrated platform that combines trade journaling, performance analytics, algorithmic trading, and AI-powered coaching in a single, cohesive system. The platform is built using modern software engineering principles and leverages cutting-edge technologies to deliver a seamless user experience across devices.

The backend of TradeOS is developed using Java Spring Boot 3.4.5, a robust and production-ready framework that provides enterprise-grade features including dependency injection, RESTful API development, data persistence with JPA/Hibernate, WebSocket support for real-time communication, and comprehensive security mechanisms. Spring Boot's convention-over-configuration approach enables rapid development while maintaining high standards of code quality and maintainability. The backend exposes a well-defined set of REST APIs that handle authentication, trade management, algorithmic strategy execution, market data retrieval, analytics computation, and AI insight generation.

The frontend is built with React 19 utilizing modern hooks, functional components, and Vite 8 as the build tool for fast development and optimized production builds. The user interface is designed with Tailwind CSS 3 for utility-first styling, ensuring a responsive, accessible, and visually appealing experience across desktop and mobile devices. State management is handled by Zustand 5, a lightweight and intuitive state management library. The frontend communicates with the backend via Axios-based HTTP clients and maintains real-time connections through STOMP over WebSocket for live market data updates.

One of the flagship features of TradeOS is its built-in Algorithmic Trading Engine. Users can create automated trading strategies with configurable entry triggers (immediate execution, price above threshold, price below threshold), position sizing, stop-loss, and take-profit parameters. The engine runs on a scheduled polling mechanism that continuously monitors market prices from an in-memory cache and evaluates strategy conditions. When conditions are met, the engine automatically executes trades and creates corresponding journal entries. A monitoring algorithm tracks open positions and closes them when stop-loss or take-profit levels are reached. Each execution is recorded with timestamps, trigger reasons, and profit/loss calculations, providing full auditability of automated trading activities.

TradeOS integrates with OpenRouter.ai to access the DeepSeek V4 Flash language model for generating intelligent insights. The platform provides three specialized AI-driven services: a trade psychology coach that analyzes trading patterns and suggests behavioral improvements; a journal coach that reviews trade entries and provides constructive feedback; and a general AI assistant that answers user queries about trading strategies, market analysis, and risk management. These AI services use carefully engineered prompts that incorporate the user's trading history and performance metrics as context, enabling personalized and actionable recommendations.

The platform aggregates real-time market data from multiple sources to ensure high availability and accuracy. For cryptocurrency prices, TradeOS primarily uses the Binance public API, which provides free and reliable price data for major crypto pairs including BTCUSDT, ETHUSDT, BNBUSDT, SOLUSDT, and XRPUSDT. For forex pairs and other instruments, the platform falls back to Twelve Data. Gold prices (XAUUSD) are fetched from goldapi.io. A caching layer implemented using ConcurrentHashMap with configurable refresh intervals ensures that frequently accessed prices are served with minimal latency while respecting API rate limits.

TradeOS is deployed on the Render Cloud Platform using Docker-based deployment for the backend and static site hosting for the frontend. The architecture follows a stateless, RESTful design pattern with JWT-based authentication, enabling horizontal scalability and future decomposition into microservices.

Keywords: Trading Journal, Algorithmic Trading, Artificial Intelligence, Spring Boot, React, PostgreSQL, Market Data, Risk Management, Docker, Cloud Deployment

EXECUTIVE SUMMARY

Project Overview

TradeOS is an integrated AI-powered trading journal and algorithmic trading platform designed to address the critical pain points faced by retail traders in today's financial markets. The project was conceived with the recognition that while financial markets have become increasingly accessible to individual traders through brokerages, the tools available to support systematic trading, performance analysis, and continuous improvement remain fragmented and inadequate.

The platform brings together four core capabilities under a single, unified interface: comprehensive trade journaling with detailed record-keeping, advanced performance analytics with interactive visual dashboards, automated algorithmic trading with configurable strategies and real-time execution monitoring, and AI-powered coaching for behavioral improvement and trading psychology analysis. By integrating these capabilities, TradeOS eliminates the need for traders to maintain multiple disjointed tools and spreadsheets, reducing friction and enabling deeper insights through cross-referencing of data across these domains.

Architecture and Technology Stack

TradeOS follows a modern client-server architecture with a clear separation of concerns between the frontend presentation layer and the backend business logic layer. The backend is a Java Spring Boot 3.4.5 application that exposes a RESTful API over HTTP and maintains WebSocket connections for real-time data streaming. The application is structured into distinct layers: controllers handle HTTP request routing and validation, services encapsulate business logic, repositories provide data access through Spring Data JPA, and entities model the database schema. Cross-cutting concerns such as authentication, authorization, rate limiting, and exception handling are addressed through Spring Security filters and global exception handlers.

The frontend is a single-page application (SPA) built with React 19 that communicates with the backend exclusively through API calls. This decoupled architecture allows independent scaling, deployment, and development of both components. The frontend is compiled into static assets by Vite 8 and served via Render's static site infrastructure. Client-side routing is managed by React Router DOM v7, with protected routes ensuring that only authenticated users can access authorized sections of the application.

Key Capabilities

Trade Journal Management: Users can log both manual and automated trades with comprehensive details including entry and exit prices, position sizes, trade direction (buy/sell), stop-loss and take-profit levels, timestamps, and free-form notes. Trades are organized by status (open/closed) and can be filtered, searched, and sorted. The journal also supports CSV import for bulk trade data migration from other platforms.

Performance Analytics: The platform computes a comprehensive set of performance metrics including win rate, profit factor, average win/loss, maximum drawdown, and risk-reward ratios. Results are presented through interactive charts built with Recharts 3 and Lightweight Charts 4, including equity curves, monthly performance heatmaps, win ratio breakdowns, and drawdown analysis.

Algorithmic Trading Engine: The built-in algo engine supports fully automated trading strategies defined by users through a strategy builder interface. Strategies consist of entry conditions (immediate, price above, price below), trade direction, position sizing, and risk parameters. The engine evaluates strategies against cached market prices at configurable intervals and executes trades automatically when conditions are satisfied.

AI-Powered Coaching: Through integration with OpenRouter.ai and the DeepSeek V4 Flash model, TradeOS provides three specialized AI services: Psychology Coach, Journal Coach, and a General AI Assistant. These services use context-aware prompting that incorporates the user's trading history and performance data.

Real-Time Market Data: Live prices from Binance, Twelve Data, and goldapi.io with intelligent caching for performance optimization.

Deployment and Operations

TradeOS is deployed on Render Cloud Platform using Docker-based deployment for the backend and static site hosting for the frontend. The database runs on Aiven Cloud PostgreSQL, providing managed database operations with automated backups, point-in-time recovery, and SSL-encrypted connections.

Chapter 1: Introduction

1.1 Background & FinTech Industry Overview

Financial Technology, commonly known as FinTech, has emerged as one of the most transformative forces in the global financial services industry over the past decade. The FinTech sector encompasses a wide range of technological innovations designed to improve, automate, and democratize financial services. From mobile banking and peer-to-peer lending to cryptocurrency exchanges and robo-advisors, FinTech has fundamentally altered how individuals and institutions interact with financial markets.

The global FinTech market was valued at approximately $340 billion in 2025 and is projected to grow at a compound annual growth rate (CAGR) of 16.5% through 2030. Within this ecosystem, trading and investment platforms represent one of the largest and fastest-growing segments, driven by the increasing accessibility of financial markets through online brokerages, the proliferation of commission-free trading, and the growing interest in retail investing.

The trading platform segment of FinTech has witnessed particularly rapid evolution. Traditional brokerages that required minimum deposits, charged high commissions, and offered limited analytical tools have been supplanted by modern platforms that provide zero-commission trading, API access for algorithmic trading, and sophisticated analytical dashboards. However, the tools available specifically for trade journaling, performance analysis, and systematic improvement of trading performance have lagged behind other areas of innovation.

1.2 Trading Industry Growth

The retail trading industry has experienced explosive growth since 2020, driven by several converging factors. The COVID-19 pandemic accelerated the adoption of digital financial services, with millions of individuals opening trading accounts for the first time. The rise of commission-free trading platforms like Robinhood, Zerodha, and Webull lowered the barrier to entry, while social trading communities on Reddit, Twitter, and Discord created new channels for information sharing and collaborative analysis.

According to industry reports, the number of retail trading accounts globally increased from approximately 100 million in 2019 to over 300 million in 2025. Daily trading volumes on major cryptocurrency exchanges regularly exceed $100 billion, while forex markets maintain their position as the largest financial market in the world with daily volumes exceeding $7.5 trillion. This growth has created a massive demand for tools that help retail traders improve their performance and navigate increasingly complex markets.

Despite this growth, the statistics on retail trading profitability remain sobering. Multiple studies across different markets and time periods consistently find that 80% or more of retail traders lose money. A 2024 study by the European Securities and Markets Authority (ESMA) found that 79% of retail CFD traders lost money, with average losses of approximately 2,000 euros per trader. Similar studies in India found that 89% of active day traders lost money in FY2023-24. These statistics underscore the critical need for tools that promote disciplined, data-driven trading practices.

1.3 Importance of Trade Journaling

Trade journaling is widely recognized by professional traders and trading psychologists as one of the most important practices for achieving consistent profitability. A trade journal is a detailed record of every trade a trader executes, including the rationale for entering the trade, the entry and exit prices, the outcome, and the trader emotional state at the time of the decision. The practice of maintaining a trade journal serves several critical functions:

  • Accountability: Knowing that every trade will be recorded and reviewed encourages traders to follow their trading plans and avoid impulsive decisions.
  • Pattern Recognition: By reviewing past trades, traders can identify recurring patterns in their behavior, such as a tendency to exit winning trades too early or hold losing trades too long.
  • Strategy Validation: Journaling enables traders to objectively evaluate which strategies are working and which are not, based on data rather than memory or emotion.
  • Continuous Improvement: Regular review of journal entries creates a feedback loop that accelerates the learning process and helps traders refine their approach over time.
  • Psychology Tracking: Recording emotional states alongside trade data helps traders identify the psychological factors that influence their decisions.

1.4 AI in Modern Trading

Artificial Intelligence has become increasingly integral to modern trading and investment management. Institutional traders have long employed machine learning models for market prediction, risk management, and portfolio optimization. However, the application of AI to retail trading has traditionally been limited to basic technical analysis indicators and simple alert systems.

The emergence of large language models (LLMs) like GPT-4, Claude, and DeepSeek has opened new possibilities for applying AI in retail trading. These models can analyze vast amounts of text data, identify patterns that might be invisible to human traders, and generate personalized recommendations based on individual trading histories. The key applications of AI in retail trading include:

  • Trading Psychology Analysis: AI models can analyze trade histories to identify behavioral biases such as loss aversion, confirmation bias, and overconfidence.
  • Pattern Recognition: AI can identify recurring patterns in successful and unsuccessful trades, helping traders understand what works for their specific style.
  • Personalized Coaching: AI can act as a virtual trading coach, providing feedback on individual trades and suggesting specific improvements.
  • Market Analysis: AI can process news articles, economic reports, and social media sentiment to provide context for trading decisions.

TradeOS leverages the DeepSeek V4 Flash model through OpenRouter.ai to provide these AI capabilities directly within the trading journal platform, eliminating the need for traders to use separate AI tools or manually export their data for analysis.

1.5 Problem Statement

Retail traders face significant challenges in achieving consistent profitability due to several systemic gaps in the available tooling ecosystem:

  1. Fragmented Tool Landscape: Traders require separate tools for journaling, analytics, market data, algorithmic trading, and news. This fragmentation creates data silos, increases cognitive load, and makes it difficult to develop a holistic understanding of trading performance.
  2. Lack of AI-Powered Insights: Most existing journaling platforms provide basic statistics but lack the ability to analyze trading psychology, identify behavioral patterns, or provide personalized coaching recommendations.
  3. No Integrated Algorithmic Trading: Traders who want to automate their strategies must use separate algorithmic trading platforms, which often require programming expertise and lack integration with journaling and analytics tools.
  4. Limited Performance Analytics: Basic metrics like win rate and total PnL do not provide sufficient insight for meaningful performance improvement. Traders need access to sophisticated analytics including equity curves, drawdown analysis, risk-reward ratios, and strategy-specific performance breakdowns.
  5. High Cost of Professional Tools: Professional-grade trading tools are often prohibitively expensive for retail traders, with popular platforms charging $30-$100 per month for premium features.

Several platforms exist in the market that address portions of the trading tool ecosystem. The following analysis examines the most prominent alternatives:

Spreadsheet Journals (Excel/Google Sheets): The most common approach to trade journaling, spreadsheet-based journals offer maximum flexibility but suffer from significant limitations. They require manual data entry, lack automated analytics, provide no data visualization capabilities, and offer no integration with market data or algorithmic trading.

Tradervue: Tradervue is a dedicated trading journal platform that offers automated trade import from brokers, basic analytics, and tagging capabilities. However, it focuses exclusively on journaling and does not provide algorithmic trading, AI coaching, or comprehensive market data integration. Premium plans start at $30/month.

Edgewonk: Edgewonk is another specialized trading journal that offers advanced analytics including expectancy calculations, Sharpe ratio, and risk-reward analysis. It provides detailed statistics but lacks AI features, algorithmic trading, and real-time market data. Available as a one-time purchase of $150-$300.

Notion Templates: Many traders use Notion templates for journaling, leveraging its flexibility and database capabilities. However, Notion lacks native trading-specific features, automated calculations, market data integration, and offers no AI coaching or algorithmic trading capabilities.

Chapter 2: Literature Review

2.1 Trading Journal Systems

Trade journaling has been recognized as a cornerstone of professional trading practice for decades. Academic research on the subject, while limited due to the relatively niche nature of the field, has consistently demonstrated the positive impact of systematic trade documentation on trading performance.

Tharp (2008) in his seminal work "Trade Your Way to Financial Freedom" emphasizes that maintaining a detailed trading journal is one of the most important practices for developing trading discipline and achieving consistent profitability. He argues that the act of writing down trading decisions forces traders to articulate their reasoning, which in turn leads to more thoughtful and less impulsive decision-making.

Steenbarger (2015) in "The Psychology of Trading" presents evidence that traders who maintain journals show faster improvement in their performance metrics compared to those who do not. His research suggests that the key mechanism is the creation of a feedback loop: journals provide data that enables objective analysis, which in turn informs strategy adjustments and behavioral modifications.

Modern trading journal systems have evolved from simple spreadsheets to sophisticated web-based platforms. The key features that distinguish advanced journaling systems include:

  • Automated Trade Import: Integration with broker APIs to automatically import trade data, eliminating manual entry errors.
  • Tagging and Categorization: The ability to tag trades with custom labels for filtering and analysis (e.g., strategy, emotion, market condition).
  • Visual Analytics: Charts and graphs that visualize performance metrics over time.
  • Export Capabilities: The ability to export data for external analysis or tax reporting.

TradeOS builds upon these established features while adding AI-powered analysis capabilities that go beyond what existing journaling platforms offer.

2.2 AI in Financial Trading

The application of artificial intelligence to financial trading has been an active area of research and development since the 1990s. Early systems focused on rule-based expert systems and simple machine learning models for pattern recognition in price data. The field has evolved significantly with the advent of deep learning, reinforcement learning, and most recently, large language models.

Machine Learning in Trading: Traditional machine learning approaches applied to trading include support vector machines (SVM) for market direction prediction, random forests for feature importance analysis, and neural networks for price forecasting. A comprehensive review by Kumar and Theodore (2023) found that while ML models can achieve predictive accuracy of 55-65% for short-term price movements, their performance degrades significantly over longer time horizons due to market regime changes and non-stationarity of financial time series.

Natural Language Processing: The application of NLP to trading has primarily focused on sentiment analysis of news articles, social media posts, and earnings calls. Research by Zhang et al. (2024) demonstrated that sentiment scores extracted from financial news using transformer-based models could provide statistically significant signals for short-term trading decisions when combined with technical analysis indicators.

Large Language Models: The emergence of GPT-4, Claude, and DeepSeek has opened new possibilities for AI in trading. Unlike traditional ML models that require labeled training data and specific prediction tasks, LLMs can perform open-ended analysis, generate natural language explanations, and adapt to a wide range of trading-related queries. Li and Chen (2025) showed that LLMs can effectively analyze trading journals and identify psychological biases with accuracy comparable to human trading coaches.

TradeOS leverages the DeepSeek V4 Flash model through OpenRouter.ai for three specific AI applications: trade psychology analysis, journal coaching, and general trading Q&A. The choice of DeepSeek V4 Flash was motivated by its strong performance on financial analysis tasks, competitive pricing, and availability through OpenRouter API infrastructure.

2.3 Algorithmic Trading Platforms

Algorithmic trading, or algo trading, refers to the use of computer programs to execute trading decisions based on predefined rules and conditions. The field has evolved from simple moving average crossovers used by institutional traders in the 1990s to sophisticated multi-factor strategies employed by quantitative hedge funds today.

Institutional Platforms: Professional algorithmic trading platforms like MetaTrader (MQL), TradingView (Pine Script), and NinjaTrader provide sophisticated strategy development environments with backtesting capabilities, custom indicators, and integration with broker APIs. However, these platforms have steep learning curves and require programming knowledge.

Browser-Based Platforms: More recent platforms like 3Commas, Cryptohopper, and HaasOnline offer simplified algorithmic trading interfaces designed for retail traders. These platforms typically support strategy creation through visual builders or simple configuration forms, reducing the programming barrier. However, they focus exclusively on execution and lack integrated journaling and analytics capabilities.

Academic Research: According to research by Chan (2021), successful algorithmic strategies typically incorporate: (1) a clear edge or source of alpha, (2) robust risk management rules including position sizing and stop-loss mechanisms, (3) rules for both entry and exit conditions, and (4) mechanisms to avoid over-optimization and curve-fitting.

TradeOS implements an algorithmic trading engine that follows these principles while providing a user-friendly interface for strategy creation. The engine supports configurable entry triggers (immediate, price above, price below), automatic position sizing, stop-loss and take-profit management, and heuristics for avoiding simultaneous competing signals. The engine is integrated with the journaling system so that all executed trades are automatically recorded for analysis.

2.4 Trading Psychology & Behavioral Analysis

Trading psychology refers to the emotional and cognitive factors that influence trading decisions. Research in behavioral finance has identified numerous cognitive biases that systematically affect trader performance:

  • Loss Aversion: The tendency to feel losses more intensely than equivalent gains, leading to holding losing positions too long and closing winning positions too early (Kahneman & Tversky, 1979).
  • Confirmation Bias: The tendency to seek out information that confirms existing beliefs while ignoring contradictory evidence.
  • Overconfidence: The tendency to overestimate ones ability to predict market movements, particularly after a series of successful trades.
  • Recency Bias: The tendency to give disproportionate weight to recent events when making decisions.
  • Anchoring: The tendency to rely too heavily on the first piece of information encountered when making decisions.

Lo and Repin (2002) conducted a landmark study using physiological measurements (heart rate, skin conductance, body temperature) to demonstrate that emotional responses significantly impact trading performance. Their research found that traders who experience stronger emotional reactions to gains and losses tend to have worse performance outcomes, suggesting that emotional regulation is a critical skill for successful trading.

TradeOS addresses trading psychology through two mechanisms. First, the journaling system allows traders to record their emotional state (emotion field in Journal entity) alongside their trade data, creating a structured dataset for analyzing emotion-performance correlations. Second, the AI-powered Psychology Coach analyzes trade histories to identify behavioral patterns and generates personalized recommendations for improvement.

2.5 Risk Management Systems

Risk management is widely regarded as the most important aspect of successful trading. Professional traders consistently emphasize that capital preservation should take priority over profit maximization. Academic research supports this view, with multiple studies finding that traders who implement systematic risk management rules outperform those who do not, even when controlling for strategy quality (Klein & Sharma, 2023).

Key risk management principles identified in the literature include:

  • Position Sizing: The Kelly Criterion and its variants provide mathematical frameworks for determining optimal position sizes based on win rate and average win/loss ratios.
  • Stop-Loss Orders: Predetermined exit points that limit losses on individual trades, preventing small losses from becoming catastrophic.
  • Maximum Daily Loss Limits: Hard limits on daily losses that trigger trading cessation to prevent revenge trading and emotional decision-making.
  • Risk-Reward Ratio: The ratio of potential profit to potential loss on a trade, with most professional traders targeting a minimum of 1:2 or 1:3.
  • Diversification: Spreading risk across multiple uncorrelated instruments to reduce portfolio volatility.

TradeOS implements risk management at multiple levels. The algorithmic trading engine includes configurable stop-loss and take-profit parameters, maximum active trade limits, and maximum daily loss limits. Chapter 3: System Analysis & Architecture

3.1 High-Level Architecture

TradeOS follows a modern three-tier client-server architecture that separates concerns into distinct layers: the presentation tier (frontend), the application tier (backend), and the data tier (database). This architectural pattern provides several advantages, including modularity, scalability, maintainability, and the ability to develop and deploy each tier independently.

Figure 3.1: High-Level System Architecture

[Architecture Diagram: Browser Client harr; Render CDN (React SPA) harr; REST API / WebSocket harr; Spring Boot Backend harr; PostgreSQL (Aiven Cloud) + External APIs (OpenRouter, Twelve Data, Binance, NewsAPI, goldapi.io)]

The frontend is a single-page application built with React 19, compiled into static assets by Vite 8, and served by Render CDN infrastructure. It communicates with the backend exclusively through HTTP REST API calls and WebSocket connections. The backend is a Java Spring Boot 3.4.5 application that processes API requests, executes business logic, manages authentication and authorization, and coordinates data access. The data tier consists of PostgreSQL 15 running on Aiven Cloud, with Flyway-managed database migrations for schema versioning.

External service integrations include OpenRouter.ai for AI model access, Binance API for cryptocurrency market data, Twelve Data for forex and index data, goldapi.io for precious metals pricing, and NewsAPI.org for financial news. All external API calls are mediated by the backend, which provides a unified interface and adds caching layers for performance optimization.

3.2 Low-Level Architecture

The backend application is structured into four distinct layers, each with specific responsibilities:

Figure 3.2: Low-Level Architecture Layer Diagram

[Layer Diagram: Controller Layer rarr; Service Layer rarr; Repository Layer rarr; Entity Layer. Cross-cutting: Security Filters, WebSocket Handlers, Exception Handlers]

Controller Layer: REST controllers handle HTTP request routing, input validation, and response formatting. Each controller is annotated with @RestController and mapped to a specific API path prefix (e.g., /api/trades, /api/auth). Controllers delegate business logic to service classes and handle HTTP-specific concerns such as extracting user identity from request attributes set by the JWT filter.

Service Layer: Service classes encapsulate all business logic and orchestrations. This layer contains the core functionality of the application, including trade management algorithms, analytics computation, AI insight generation, and algorithmic trading engine execution. Services are annotated with @Service and injected into controllers via constructor-based dependency injection.

Repository Layer: Spring Data JPA repositories provide data access abstractions over the PostgreSQL database. Each entity has a corresponding repository interface that extends JpaRepository, providing standard CRUD operations, pagination, and sorting. Custom queries are defined using @Query annotations with JPQL or method naming conventions.

Entity Layer: JPA entities model the database schema as Java classes, with annotations mapping each field to a database column. Relationships between entities are defined through foreign key references rather than JPA relationship annotations, maintaining a lightweight data model.

Cross-Cutting Concerns: The security architecture implements authentication and authorization through a JWT filter that intercepts all incoming requests, extracts and validates JWT tokens, and sets the authenticated user email as a request attribute. A rate limit filter provides basic protection against API abuse. Global exception handling is implemented through @ControllerAdvice.

3.5 Security Architecture

The security architecture implements defense-in-depth principles through multiple layers of protection:

Figure 3.5: JWT Authentication & Authorization Flow

[Flow Diagram: Client rarr; POST /api/auth/login rarr; Validate credentials rarr; Generate JWT rarr; Return token rarr; Subsequent requests include Bearer token rarr; JwtFilter validates rarr; Set email attribute rarr; Controller processes request]

Authentication: JWT-based authentication. When users log in with valid credentials, the backend generates a signed JWT containing the users email and role. The token is signed using the JWT_SECRET environment variable. The client stores the token in localStorage and includes it in the Authorization header of all subsequent API requests as a Bearer token.

Authorization: The JwtFilter intercepts all incoming HTTP requests (except public endpoints). It extracts the JWT from the Authorization header, validates the signature and expiration, and sets the user email as a request attribute. Controllers and services use this attribute to enforce data-level access control.

Rate Limiting: The RateLimitFilter provides basic protection against brute-force attacks by limiting requests from a single IP within a configurable time window.

4.5 JWT Authentication Flow

  1. User submits credentials via POST /api/auth/login
  2. UserService validates email/password against database (BCrypt)
  3. On success, JwtUtil generates a signed JWT with user email as subject
  4. Token returned to client, stored in localStorage (key: tradeos_token)
  5. Subsequent requests include Authorization: Bearer {token}
  6. JwtFilter extracts token, validates signature and expiration
  7. If valid, user email is set as request attribute for downstream processing
  8. If invalid/expired, returns 401 Unauthorized

Chapter 5: Implementation & Module Description

5.1 Authentication Module

Purpose: The Authentication Module handles user registration, login, profile management, and password reset operations. It is the first point of interaction for users and establishes the security context for all subsequent operations.

Workflow: Registration requires full name, email, and password. The password is hashed using BCrypt with a configurable strength factor before storage. Login validates credentials against the stored hash and returns a signed JWT token upon successful authentication. The JWT token encodes the user email and is signed using the HMAC-SHA256 algorithm with the configured secret key. Token expiration is set to 24 hours from issuance.

Key Files: AuthController.java, UserService.java, JwtUtil.java, JwtFilter.java, SecurityConfig.java

Figure 5.1: Registration Workflow

[Flow: User fills registration form rarr; POST /api/auth/register rarr; UserService validates input rarr; BCrypt encodes password rarr; UserRepository saves to DB rarr; Returns success message]

Figure 5.2: Login & JWT Issue Flow

[Flow: User submits credentials rarr; POST /api/auth/login rarr; UserService finds user by email rarr; BCrypt matches password rarr; JwtUtil generates token rarr; Returns token + user data JSON]

Features:

  • BCrypt password hashing with automatic salting
  • JWT token generation with configurable expiration
  • Password reset with UUID-based tokens
  • Profile retrieval and update with role information
  • Role assignment (default: TRADER) on registration

Benefits: Stateless authentication eliminates server-side session storage, enabling horizontal scaling. JWT tokens are self-contained and can be validated without database lookups.

5.2 Trade Journal Module

Purpose: The Trade Journal Module is the core feature of TradeOS, providing comprehensive trade management with CRUD operations, search, filtering, pagination, CSV import/export, and advanced trade management features like partial closing and stop-loss/take-profit updates.

Workflow: Users create trades by specifying symbol, trade type (BUY/SELL), entry price, stop-loss, take-profit, position size, and optional metadata (session, strategy, timeframe, confidence). Trades can be opened and later closed with exit price and final PnL calculation. The module supports advanced operations including moving stop-loss to breakeven, partial position closing, and updating SL/TP levels on open trades.

Features:

  • Complete CRUD operations (Create, Read, Update, Delete)
  • CSV import for bulk trade data migration from other platforms
  • CSV export for external analysis or tax reporting
  • Search by keyword across symbol, notes, and strategy fields
  • Pagination with configurable page size for large trade histories
  • Filtering by status (open/closed) and symbol
  • Advanced: move to breakeven, partial close, update SL/TP
  • Trade notes with rich text support

Benefits: Eliminates manual spreadsheet maintenance, reduces data entry errors through structured forms, provides instant PnL calculations, and enables data-driven trading decisions through comprehensive trade history access.

5.3 Analytics Module

Purpose: The Analytics Module computes key trading performance metrics and provides interactive visualizations to help traders understand their strengths, weaknesses, and areas for improvement.

Computed Metrics:

  • Win Rate: Percentage of closed trades that were profitable
  • Profit Factor: Gross profit divided by gross loss (values above 1 indicate profitability)
  • Average Win/Loss: Mean profit of winning trades and mean loss of losing trades
  • Maximum Drawdown: Largest peak-to-trough decline in account equity
  • Sharpe Ratio: Risk-adjusted return measure
  • Risk-Reward Ratio: Average win amount divided by average loss amount
  • Monthly PnL: Profit/loss broken down by calendar month
  • Streak Analytics: Longest consecutive win and loss streaks
  • Performance by Symbol: Win rate and PnL breakdown by trading instrument

Benefits: Provides objective, data-driven performance assessment without emotional bias. Enables traders to identify which strategies and instruments perform best for their specific trading style.

Purpose: The AI Module leverages the DeepSeek V4 Flash language model through OpenRouter.ai to provide intelligent coaching, psychology analysis, and trading assistance. It comprises three specialized AI services.

Services:

  • Journal Coach (TradeJournalAiService): Reviews individual journal entries and provides constructive feedback on trading decisions, risk management, and adherence to trading plans.
  • General AI Assistant (DeepSeekAiService): Answers user queries about trading strategies, market analysis, risk management, and general trading concepts.
  • Insights Generator (AiInsightsService): Produces daily/weekly performance summaries with AI-generated observations and suggestions.

5.6 News Module

Purpose: The News Module fetches and displays financial news relevant to the traders interests, including cryptocurrency, forex, and general market news.

Implementation: NewsService calls the NewsAPI.org REST API with a query filter for crypto, bitcoin, and forex keywords. Results are sorted by publication date and filtered for English language articles. The backend returns the raw API response to the frontend for rendering in the NewsCard component.

Benefits: Eliminates the need to switch to separate news aggregators, keeping market-relevant information within the trading platform context.

5.7 Algorithmic Trading Module

Purpose: The Algorithmic Trading Module is one of the flagship features of TradeOS, enabling users to create, configure, deploy, and monitor automated trading strategies without requiring programming knowledge.

Architecture: The module consists of three core components:

  • Strategy Management: AlgoStrategyController and AlgoStrategyService handle CRUD operations for trading strategies. Each strategy defines the instrument, trade direction, entry conditions, risk parameters, and execution constraints.
  • Execution Engine: AlgoEngineService is a scheduled service that runs at configurable intervals (default: 5 seconds) and evaluates all active strategies against current market prices. When a strategies entry conditions are met, the engine automatically creates a trade record and an execution log entry.
  • Execution Monitor: The same engine also monitors open executions and closes them when take-profit or stop-loss levels are breached, creating complete audit trails.

Strategy Configuration: Users can configure the following parameters:

  • Entry Triggers: IMMEDIATE (execute at next poll), PRICE_ABOVE (execute when price rises above threshold), PRICE_BELOW (execute when price falls below threshold)
  • Risk Controls: Stop-loss price, take-profit price, position size, maximum active trades, maximum daily loss
  • Instrument: Any supported symbol (XAUUSD, BTCUSDT, ETHUSDT, etc.)
  • Direction: BUY (long) or SELL (short)

[Cycle: @Scheduled trigger rarr; Load active strategies from DB rarr; Get current price from PriceCache rarr; For each strategy: evaluate entry conditions rarr; If conditions met: create Trade + AlgoExecution rarr; For open executions: check SL/TP rarr; If breached: close trade, calculate PnL, update execution]

Benefits: Enables 24/7 automated trading without manual intervention. Eliminates emotional decision-making from trade execution. Provides full auditability with detailed execution logs linked to both strategies and trades.

5.8 Admin Module

Purpose: The Admin Module provides system administration capabilities for managing users, monitoring system health, and configuring platform-wide settings. Access is restricted to users with the ADMIN role through RoleRoute guards on the frontend.

Implementation: The AdminDashboard page is served under the /admin route and wrapped in both ProtectedRoute and RoleRoute components. The backend enforces admin-level access through role checks in service methods. AdvancedAnalyticsController provides system-wide analytics and user management capabilities.

Benefits: Centralized management interface for platform administrators, enabling user oversight and system monitoring without database-level access.

Basic Level (Questions 1-25)

Q1: What is TradeOS?

A: TradeOS is an AI-powered trading journal and algorithmic trading platform built with Spring Boot and React that helps retail traders log, analyze, and automate their trades.

Q2: What problem does TradeOS solve?

A: It solves the fragmentation of trading tools by integrating journaling, analytics, algorithmic trading, and AI coaching into a single platform, eliminating the need for multiple disjointed tools.

Q3: What technology stack is used?

A: Frontend: React + Vite + Tailwind CSS. Backend: Java Spring Boot 3.4.5. Database: PostgreSQL on Aiven Cloud. Deployment: Render with Docker.

Q4: What is the database used?

A: PostgreSQL 15 hosted on Aiven Cloud, a managed cloud database service with SSL encryption and automated backups.

Q5: How is user authentication implemented?

A: Using JWT (JSON Web Tokens). Users login with email/password, get a signed JWT, and include it in the Authorization header for subsequent requests.

Q6: What is the frontend framework used?

A: React 19 with functional components and hooks. Vite 8 is used as the build tool for fast development and optimized production builds.

Q7: What styling approach is used?

A: Tailwind CSS 3, a utility-first CSS framework that enables rapid UI development with responsive design.

Q8: What is the role of Spring Boot in this project?

A: Spring Boot provides the backend framework for building REST APIs, handling dependency injection, database access via JPA, security, and WebSocket communication.

Q9: What is JWT and why is it used?

A: JSON Web Token is a compact, URL-safe token format used for stateless authentication. It is used because it eliminates server-side session storage, enabling horizontal scaling.

Q10: What external APIs does TradeOS integrate with?

A: OpenRouter.ai (AI model access), Binance API (crypto prices), Twelve Data (forex/indices), goldapi.io (gold prices), and NewsAPI.org (financial news).

Intermediate Level (Questions 26-50)

Q26: How does the algorithmic trading engine work?

A: The engine runs on a scheduled @Scheduled method that polls every 5 seconds. It loads active strategies from the database, fetches current prices from the cache, evaluates entry conditions, and executes trades automatically when conditions are met.

Q27: How is AI integrated into TradeOS?

A: Through OpenRouter.ai API, which provides access to the DeepSeek V4 Flash model. The backend constructs context-rich prompts with user trading data and sends them to the API for processing.

Q28: What is the role of BCrypt in the application?

A: BCrypt is used for password hashing before storing user passwords in the database. It automatically generates a unique salt for each password and is resistant to brute-force attacks.

Q29: How does the price caching mechanism work?

A: PriceCacheService uses a ConcurrentHashMap to store symbol-to-price mappings. It runs a scheduled task that refreshes prices at configurable intervals (default 5 seconds) by calling LiveMarketService for each active symbol.

Q30: Explain the JWT filter chain.

A: The JwtFilter extends OncePerRequestFilter and is added before UsernamePasswordAuthenticationFilter in the Spring Security chain. It extracts the Bearer token, validates it using JwtUtil, and sets the user email in the SecurityContext.

Advanced Level (Questions 51-75)

Q51: How would you scale TradeOS for thousands of users?

A: The stateless JWT-based architecture already supports horizontal scaling. We would add a Redis cache layer, implement database read replicas, use a message queue (RabbitMQ/Kafka) for algo engine tasks, and deploy multiple backend instances behind a load balancer.

Q52: How does the algorithm engine handle concurrent strategy execution?

A: Each strategy evaluation is wrapped in a try-catch block to prevent one failing strategy from affecting others. The @Scheduled method runs in a single thread, but for scale, we could use a ThreadPoolTaskScheduler with configurable pool size.

Q54: How would you implement broker API integration?

A: By creating a BrokerAdapter interface with implementations for each broker (OANDA, Binance, MetaTrader). Each adapter handles authentication, order placement, and position retrieval. The TradingAccount entity stores encrypted API credentials, and a BrokerSyncService manages periodic synchronization.

Q55: How does the system handle database connection failures?

A: HikariCP connection pool is configured with connection timeout (20s), idle timeout (5min), and max lifetime (20min). If connections fail, HikariCP automatically retries. The application also uses Spring retry for critical database operations.

Q56: What is the data isolation strategy between users?

A: All data tables include a user_email column. Every service method filters by the authenticated user email extracted from the JWT. This ensures that users can only access their own data, even if they somehow obtain another users ID.
